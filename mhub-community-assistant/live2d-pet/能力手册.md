# 大肥鱼 Live2D 身体能力手册 v1

本手册现由迈从大肥鱼内置 Live2D 提供。动作与渲染规则沿用作者版本；实现备忘中的宿主事件说明保留为历史背景，实际事件路由由项目内 `live2d/host.mjs` 提供。无需外部 AuraBot 或 Live2D 插件。电话与语音条不冒充 Harness 任务。

> 这是给大肥鱼自己看的「身体说明书」：她知道自己有哪些动作和表情，每句话当场决定用不用、用哪个。
> 模型：DeepSeek-chan（大肥鱼），原画及拆分：神宫凉子，Live2D 建模：霓虹猫_NeonNeko（神宫凉子免费配布模型）。
> 2026-11-05 由 model3.json 自动注册生成，渲染验证已通过（Cubism 5 Core + pixi-live2d-display，加载 394ms）。

这 15 个的幅度不是拍脑袋定的，是 2026-11-06 用探针逐参数截图测出来的（`.frames/` 里存着）：

- **头角度 ±20° 才「一眼读出情绪」**，±10° 在近景里几乎看不出来 → 这批普遍给 18~24°。
  再叠上物理链的衰减（输入 -20° 最终只到 -13°）和待机基线本身的 +7° 仰头，
  所以「垂头」类动作按 1.2 倍补偿（叹气写 -24，实际垂到 -14 左右）。
- **手只有两种写法**：`Param36 ≥0.7`（手进画面，会触发镜头后退）或干脆不抬手。
  0.3~0.5 的中间值在取景里根本看不见，纯浪费 —— 所以「犹豫 / 打量 / 凑近看」都不抬手。
- **`CheeckPuff`（鼓脸）写满 0.9 也没有可见变化**（部件可能另有开关），
  所以「鼓脸」改叫「赌气」，改用「快速扭头 24° + 抬下巴 + 梗住不动」表达，比鼓脸更读得出来。
- **`ShoulderY` / `ChestY1` / `LeanInput` 单用画面变化很弱**，只能当辅助，不能承载语义。
  真正好用的三个信号是：头角度、嘴张开、眼睛开合。


写法和原生动作一样：`<body:害羞,脸红>`。库里没有的名字会被忽略并记一条日志。

**为什么以前只能「抬个手」**：这套骨架是两段式的，`RArm` 只让手臂在身侧张开约 30°，
真正抬手要靠 `Param36`（右大臂 Z）。所有关节的实际方向都是逐个截图测出来的，
完整用法见 **`关节词典.md`**（她造动作前会读它）。

**取景（2026-11-06 重写，别再按画布算）**：以前的「上半身特写」按**画布**取景 ——
画布 3749×7697，但内容只占 x 545..3706、y 764..7325，两侧全是透明留白。
按画布居中取景，可见宽度只覆盖内容宽的 48%，于是**两侧长发被切断**（先生报的问题）。
现在改成按**内容包围盒**取景，并加一道宽度硬约束：

- 内容宽 3161 单位必须整幅塞进窗口，否则切头发 → 取景距离有下限 `uByWidth`
- 再留 15% 余量，兜住三件事：待机微摆（头发左右晃 ~7px）、动作重心侧移（10~17px）、
  抬手臂时内容变宽（+10%）
- 水平按**内容中心**（x=2125.5）对齐，不是画布中心（1874.5）——本模型尾巴在右，
  按画布居中会白裁右侧 251 单位

结果：**窗口已加宽到 720×780**（2026-11-06），取景距离约 3840 单位，是标准上半身特写（到腰）。
窗口宽度是唯一能同时买到「脸大」和「头发完整」的手段，因为两者的商就是取景距离：

| 窗宽 | 取景距离 | 可见范围 | 底部切掉 | 脸部高度 |
|---|---|---|---|---|
| 380 | 7242 | 全身 | 0% | 113px |
| 480 | 5742 | 到小腿 | 12% | 143px |
| 560 | 4926 | 到大腿 | 25% | 167px |
| 640 | 4314 | 到裙摆 | 34% | 191px |
| **720** | **3836** | **到腰（上半身）** | **42%** | **214px** |

改动只在一处：`app/main.js` 的 `WIN_W`（可用 `PET_W=560 node start.cjs --debug` 临时覆盖试档）。
取景距离由上面的公式自动反算，改宽度不用动别的常量。

**动作期间会额外退让 0~30%**：窗口越窄，同样的重心侧移在屏幕上放大得越多（720 宽时约 1.9 倍），
不退让就会出现「欢呼切掉指尖、摊手切掉整只手掌」。退让是 0.35s 平滑的，观感等于「演大动作时镜头拉远」。
映射区间 `armMag 0.2~0.45 → 0~1`：摊手只抬 0.4 却很横，用 0.3~0.7 的老区间时它只换算出 0.25、退不够。

**气泡不跟窗口满宽**：加宽后满宽气泡会变成 692px 的横幅，已限制 `max-width: 340px` 居中。

**动作让位**：播带手臂的动作时镜头再退 0~12%（`gestureK` 按 `armMag` 0.3~0.7 线性渐变，
0.35s 平滑追上），免得手冲出画框。极端动作（欢呼双手举高）仍会让手指尖擦边 —— 这是取舍，
再退就是「一动手画面就缩一圈」，比轻微出画更难看。

**手型有粘性**：原生「举手 / 竖手指」会把 `Movement2/3` 置 1 且播完不还原，
两套叠一起手就变形。两条路要分清（2026-11-06 逐 150ms 采样实测）：
- **有动作在播时**不能写 `Movement*`：动作每帧重写这个开关，写完当场被算回去。
  这时只能播模型自带的「收手 / 收手指 / 收狗尾草」去关；
- **没有动作在播时**（先 `stopAllMotions()`）直接写 0 就定住了（实测 1 秒后仍为 0）。

收手要 **635ms** 才归零、残留彻底衰减到 1.9 秒，所以切形态的等待是 720~950ms
（原写 380ms 太早，新形态一播就叠成两套 —— 「指人」之后演什么都手畸形，根因就在这）。
复位按钮走「停动作 + 写 0 + 回待机」，所以是瞬时的，不用等。

**看效果 / 验收**：迈从大肥鱼后台「Live2D 桌宠」里有一张「动作库」卡片，
每个动作一个按钮，点一下她当场演一遍（不弹气泡、不出声，纯看形体）。
清单每次现读 `clips.json`，所以她自己新造的动作几秒内就会出现在列表最前面、带「新」标记。
接口：`GET /api/mhub-community/live2d/ext/live2d/clips`（清单）、`POST /api/mhub-community/live2d/ext/live2d/play`（`{"name":"挥手"}`）。

**复位按钮**：动作库卡片底部「↺ 复位到初始状态」。它比自动归位更彻底，一次收掉五样：
在播的动作 clip、手型开关（直接归零）、表情层（resetExpression）、姿势（自然）、
思考态（连三点气泡）、说话层（停声、清包络）。物理输入不用手动清 —— clip 一停下帧就归零。
**保留**待机微摆与呼吸：那是她的底噪，属于「初始状态」，不是残留。
接口：`POST /api/mhub-community/live2d/ext/live2d/reset`。

## 一、原生状态动作（8 个，开关型）

| 她写的名字 | 身体效果 |
|---|---|
| `举手` | 从默认姿势抬起手，举起来 |
| `收手` | 把举起的手放回默认姿势 |
| `掏狗尾草` | 掏出狗尾草叼上（悠闲/得意） |
| `收狗尾草` | 把狗尾草收回去 |
| `竖手指` | 竖起食指（要说话了/强调/有想法） |
| `收手指` | 把竖起的食指放下 |
| `脱鞋` | 脱掉鞋子（放松/居家/耍赖） |
| `待机` | 回到默认待机呼吸（不动也是一种选择） |

注意：动作是「状态切换」型——`掏狗尾草` 之后她会一直叼着，直到 `收狗尾草`。这正好符合"她的心情持续影响她的姿态"的表达方式。

## 二、表情（叠加在动作上，可随时切换，下一个表情覆盖上一个）

**情绪类（日常表达主力）：**
`脸红`（害羞/被夸）、`＞＜`（大笑/兴奋/喊叫）、`黑脸`（无语/生气/不爽）、`爱心眼`（超喜欢/心动）、`圈圈眼`（晕/懵/震惊）、`屑屑眼`（傲娇/不服/星星屑）、`流冷汗`（尴尬/心虚）、`流泪`（委屈/难过/感动）、`兔牙`（开心露齿笑）

**状态/道具类（换装与小剧场）：**
`前倾`（凑近看）、`胸口衣服`、`脱鞋`（居家状态）、`竖食指开/关`

> `单片眼镜`、`黑框眼镜`、`钢盆`、`尾巴开关`、`裙子切换`，加上 `体型1`、`体型2`、`默认体型` 这八个从 v0.8.0 起**不算表情了**，改归「长相」（见第四节·七）。它们本来是模型的 Add 型 Expression，和常驻外观改同一批参数，两套并存会互相压——现在统一走常驻外观通道，写 `<body:,钢盆>` 仍然管用，语义从「演一下」变成「戴上了就一直戴着，再写一次才摘」。

## 二·五、长相（常驻外观，v0.8.0）

和表情最大的区别：**不会自己变回去**。戴了眼镜就一直戴着，换了短裙就一直穿着，重启桌宠也还在。

| 项目 | 可选 | 怎么写 |
|---|---|---|
| 体型 | 默认 / 中 / Q 版 | `<body:,默认体型>`、`<body:,体型1>`（中）、`<body:,体型2>`（Q 版） |
| 眼镜 | 不戴 / 黑框 / 单片 | `<body:,黑框眼镜>`、`<body:,单片眼镜>`（再写一次摘掉；两副互斥） |
| 大钢盆 | 戴 / 不戴 | `<body:,钢盆>` |
| 裙子 | 短裙（默认，露腿）/ 长裙（及踝） | `<body:,裙子切换>` |
| 尾巴 | 有（默认）/ 无 | `<body:,尾巴开关>` |

体型三档不是「相机拉远」，是模型真的变形 —— 腿缩短、头相对变大。**三档各有一份自己的取景配方**，不是同一套公式套出来的缩放：

| 档位 | 半身视图（bust） | 全身视图（full） | 做抬手动作 |
|---|---|---|---|
| 默认 | 上半身特写，画面到腰，脸最大 | 站满画面高度 | 镜头退 30% |
| 中 | 单独的**半身像**：头顶留一点空，画面到腰胯 | 站满画面高度 | 镜头退 34% |
| Q 版 | 小小一只完整小人，上下留白均匀 | 缩小到 85% 并居中（不再是巨婴） | **完全不退** |

Q 版做动作时镜头不退，是刻意的：她本来就占不满画面，再退只会显得「莫名其妙地缩小」。代价是脸小 —— Q 版说话时嘴形只有默认档的四分之一大。

三种改法效果一样，挑顺手的：
1. 标签：`<body:,钢盆>` —— 最快，跟说话一起发出去；
2. 工具：`live2d_look` —— 能问「我现在什么样」，也能改，还能处理「主人说换个样子」这种模糊说法；
3. 面板：主人自己在设置页点（不经过她）。

两条实测注意：
- **大钢盆会盖住上半张脸**（眼睛只露下半），搞笑效果满分，但别长期戴着说话——情绪全被盆挡掉了。
- 尾巴在默认档的上半身特写里看不到（画面只到腰），要做抬手类动作镜头后退时才露出来。所以「收尾巴」这个开关在静止时看不出差别，是正常的，不是坏了。切到「中」或全身视图时也能看到。

## 三、姿势（M3 新增：头颈身体的姿态，叠加在动作和表情之上）

| 她写的名字 | 身体效果 |
|---|---|
| `歪头` | 头一歪 + 眯眯笑眼（歪头杀，卖萌主力） |
| `抬头` | 仰起头（得意/望天/叹气前的深呼吸） |
| `低头` | 垂下头（害羞/沮丧/认错） |
| `转头` | 脸侧过去看别处（不理人/注意到什么） |
| `侧倾` | 整个身子往一边靠（放松/偷看） |
| `后仰` | 往后靠着（摊着/舒展/松一口气） |
| `前探` | 上半身凑近看一眼（好奇/关切/打量） |
| `挺胸` | 微抬下巴 + 睁大眼（神气/自信满满） |
| `抚胸` | 手抚胸口（郑重/安心/惊讶后的平复；开关型） |
| `自然` | 收掉姿势回正 |

姿势是「叠加」型：加在动作和眼神追踪之上，不锁死视线；新姿势覆盖旧姿势，`自然` 收掉。
（原 `并腿` 姿势已删除：它写的 `Param33` 是物理输出参数，写进去会被物理引擎覆盖，实际无效。）

**她自己会自动跟着您的鼠标看**（v3）：不用写标签，只要您在屏幕任何位置移动鼠标，她的眼睛、头、
上半身都会跟着转——鼠标离得越远转得越多，鼠标在她下方时还会微微前倾低着头看。所以姿势词只用在
「想主动做一个明确姿态」的时候，日常跟随是身体自发的本能。

**演出期间会暂时脱离鼠标追踪**：只要这句带了动作/表情/姿势，注视跟随就淡出，头部完全交给
姿势，避免「跟着鼠标转」和「歪头做表情」互相拉扯；归位时（说完话 +3.5s）自动恢复跟随。

## 四、每句话怎么带动作（输出格式）

在回复末尾追加一个标签，壳会剥掉它再发 QQ，标签本身永远不会出现在聊天里：

```
<body:动作名,表情名,姿势名>
```

规则：
1. **肢体语言要积极**：说话时尽量带个动作（举手、竖手指、掏狗尾草都很日常），光换表情不动手会显得木讷。
2. 三段都可省略：只换表情写 `<body:,脸红>`；只做动作写 `<body:举手>`；只摆姿势写 `<body:,,歪头>`。
3. 三段可任意组合出丰富演出：得意地歪着头竖手指 `<body:竖手指,爱心眼,歪头>`；害羞地垂着头 `<body:,脸红,低头>`；委屈巴巴 `<body:,流泪,低头>`。
4. 动作是状态切换型（做了保持到反向动作），不用每句都写。但她说**完这句话大约 3.5 秒后**就会**自己松下来**（姿势回正、手收回、表情归位全在同一刻发生），想保持某个状态就再写一次标签——所以长动作别指望靠一句话扛一整段。
5. 句末**最多一个 `<body:>`**（一个动作 + 一个表情 + 一个姿势）；句中的 `〔〕` 最多 4 个（见 四·六）。
6. 名字必须用本手册里的名字。写错身体不会有反应，但模块会记下她写错的原词 + 编辑距离最近的动作名，**下一轮的手册末尾多一行「你是不是想写 XX」**——她自己能改过来（v0.6.0）。
7. 动作要贴合情绪：得意时举手挺胸、思考时叼狗尾草歪头、撒娇时竖手指。
8. 别人要求做具体动作时，从手册里找最接近的照做；手册里没有的就直说做不到。

## 四·五、动作修饰符（v0.6.0，借鉴 WHALEL2D）

同一个动作加修饰词，语义可以完全不同 —— 这是「表达力」的真正来源，不是动作数量。
语法写在动作名前，可叠加，也可用空格分隔：

| 修饰 | 效果 | 例子 |
|---|---|---|
| 微 / 小 / 大 / 狠 | 幅度 ×0.5 / 0.7 / 1.4 / 1.6 | `微点头`＝轻轻示意，`大点头`＝用力肯定 |
| 快 / 慢 | 时长 ×0.65 / 1.7 | `快点头`＝催促惊疑，`慢点头`＝深思后了然 |
| ×N | 连做 N 次（≤5） | `快点头×3`＝「真的吗？！」连问 |
| :左 / :右 | 镜像到另一侧 / 原样 | `指人:左` |

叠加写法：`<body:微快摇头×2>`、`<body:慢 大 伸懒腰>`、`<body:指人:左,屑屑眼>`。

实测（2026-11-06 截图对照）：
- 大挥手 → 双臂抬到头侧、镜头自动退开；微挥手 → 只抬到胸口、镜头不动。同一个动作两种社交含义。
- `×N` 是原地连贯重播（不重新起手），手臂不会「回到起点再抬一次」。

实现要点（不是给她看的）：
- 模块侧 `parseMotionSpec()` 解析，编码进 anim 的**第 4 段** `@幅度|时长|重复|L`（段内用 `|`，因为整串 anim 用逗号分段）。
- pet 服务对 anim 有 `slice(0,40)` 硬上限 → `animOf()` 超长时按「先丢姿势、再丢表情」保住动作和修饰。
- 渲染页 `playClip({amp, speed, repeat, mirror})`：**显式给了修饰就不再随机抖动**（否则「慢点头」会被 ±12% 随机数吃掉语义）；没修饰时照旧抖，保证同一动作不重复。

## 四·六、句中动作（v0.7.0）—— 说哪儿动哪儿

句末一个 `<body:>` 等于「整句话只有一个状态」。真实的人说话时身体是分段动的：
先歪头听（表示在听）、再点头（表示认同）、最后摊手（表示没办法）。所以动作要能挂在句子的某个位置。

```
我泡了热茶，〔歪头听〕你先坐下来歇会儿〔微点头〕别急着忙
```

- 用 `〔〕` 括起来，一句最多 4 个，按出现顺序依次触发。
- 括号内和 `<body:>` 同一套语法：`〔微快点头×3〕`、`〔点头,脸红〕`、`〔脸红〕`（只写表情）。
- **时间由渲染端算，她不用管**：模块只解析出「第几个字之后做什么动作」，渲染端拿这句语音的真实时长反推语速。
- **动作节奏跟后文**：一个动作该演多快，取决于它后面还有多少话 —— 后面还有很多字就慢慢做完，
  后面马上收尾就快一点。系数夹在 0.7~1.6（再慢像卡住、再快像抽筋）。她显式写了「快/慢」就听她的。
- 句末 `<body:>` 依然有用：它管整句的基调和收尾（表情、姿势、最后一个动作）。

实测（2026-11-06，真实链路）：
- 18 字 / 4.15s → 4.3 字/秒；两个动作实际间隔 1860ms，按语速算 1840ms，误差 20ms。
- 整体会有 ~2.5s 偏移，那是 DSH 合成 TTS 的耗时，不是排程误差（两个动作偏移量完全一致）。

实现要点（不是给她看的）：
- 协议：模块写 `state/live2d/pet/beat.json`（渲染页静态服务伺服这个目录），`anim` 字段只传 `beat:<id>`。
  为什么不塞进 anim：pet 侧有 `slice(0,40)` 硬上限，多动作脚本必然超长。
- **音频时长必须自己测**：payload 里的 `durationMs` 实测错得离谱（报 1200ms，真实 4.32s，差 3.6 倍），
  照它排会把整句动作挤进前 1.2 秒。渲染端用 `decodeAudioData` 探（和播放同一条路径），
  `new Audio()` 读 metadata 在 Electron 里会挂住不回调，白等一秒半。
- **必须用副本探测**：`decodeAudioData` 会 detach 底层 ArrayBuffer，而 `playVoice` 是紧跟着异步跑起来的 ——
  等 fetch 完 beat.json 再读 `d.audio`，长度已经是 0（踩过，表现为 probe 恒为 0）。
  所以要在 `applyScript` 的**同步前缀**里先 `slice(0)` 复制。
- 每字时长下限 100ms（≈10 字/秒）：TTS 偶尔念得极快，全按真实语速铺会把几个动作挤成一团看不清。

## 五、给壳的实现备忘（不是给她的）

- **M2/M3 联动模块**：`mhub-community-assistant/live2d/core.mjs`（项目内集成版）
  - `api.rule()` 注入手册（默认仅私聊 kind=private；面板可切私聊+群聊）
  - `api.on('reply')` 剥标签 → `api.use('pet').dispatch({ text, modality:'voice', anim:'动作,表情,姿势', via:'pet', noFallback:true })`
  - **DSH 窗口直聊旁路**（v0.3.1）：`api.dsh.on('session/event')` 监听窗口直打回合（source.kind==='user'），带标签的回复剥标签后投桌宠；只认带标签的回复（防止编程代理的话冒充她）；4 秒同文本去重防与 QQ 管道双发。窗口里标签会显示原文（session/event 是只读旁路，无法改写窗口显示）。
  - **动作复位**（v0.3.4，2026-11-06 再改）：**按这句实际说了多久来算窗口**——`语音时长 + 3.5s 余韵`，夹在 4.5~20 秒之间；到点一次性做完「姿势回正 + 反向动作收回 + 表情归位 + 交还注视」。每说一句重算（可长可短，不会被上一句的长窗口粘住）。依据：实测 pet 语音缓存 47 条，中位 2.0s、平均 2.3s、最长 5.9s，91% 在 4 秒内 —— 原来固定 30 秒等于说完还端着十几倍时间，先生反馈「等太久、不自然」。
- **思考态（2026-11-06，DSH 状态驱动）**：宿主在「想」的时候她自己也入戏，不用谁下指令。
  - **数据来源**：DSH 的 pet 服务自带工作状态机（`thinking / working / result / waiting / success / error`，见 `dsh-aurabot-qq/src/modules/pet/index.js` 的 `WORK_STATE_LABEL` + `onSessionEvent`），**状态一变就 emit 一个 `{type:'work', state, label}` 到 `/events`**。桌宠是长轮询客户端，主进程原本只处理 `proactive/behavior/focus`、`work` 那条写着「M1 暂不处理」——现在接上了。触发点：`turn/start` → thinking、`tool/call` → working、`tool/result` → result、`turn/end` → success/error/null。**不区分 QQ 还是窗口直聊**（都是同一个 DSH 会话），所以两种场景都会触发。
  - **表现**：头歪 12° + 微仰 9° + 侧转 8°（走物理输入，头发/耳朵/蝴蝶结一起跟），眼睛半眯（乘性 ×0.68）、眉毛微垂 −0.28、眼球在斜上方**每 1.2~2.8 秒换一个注视点**（像在脑内翻找答案）；头顶右侧挂三点小气泡（`#think`，纯 CSS 动画，无文字）。working 时眼球改朝**下**（盯着手上的活），result 沿用 working 姿态——否则工具链里 states 反复跳会每跳闪一下。
  - **幅度不是拍脑袋定的**（`tkprobe.cjs`）：只给 6~8° 时画面动了 68% 像素却「读不出在想事」；真正让语义成立的是**歪头 + 半眯眼**（combo 探针一眼就像在琢磨），漂移正弦只负责「不死板」。眼球单参数效果很弱（`ParamEyeBallY=1` 只 8.4% 像素变化），不能指望它表达情绪。
  - **优先级**：低于说话与动作——`onSpeak` 一进来就 `setThinking(false)`（以「说出口」为准，不等宿主的 turn/end）；有动作/姿势/注视被 hold 时思考层只留三成，不抢戏；思考期间随机微动作自动让路。
  - 钩子：`__setThinking(true,'thinking'|'working')`、`__thinkState()`。
- **物理输入驱动**（渲染端 v2，2026-11-06）：姿势与注视**不能再写 `ParamAngleX/Y/Z`**——这三个是本模型物理链的输出（`AngleX` →弹簧→ `ParamAngleX`），写它会被下一帧物理覆盖，且头发/帽子/蝴蝶结/耳环全都不跟随。正确做法：写物理输入 `AngleX/AngleY/AngleZ/PositionX/Y/Z/LeanInput`，并**在 `physics.evaluate` 之前**注入（已劫持该方法），物理据此算出 `ParamAngle` 并联动整组零件。实测对比：物理前写 `AngleX=30` 头转+头发甩；写 `ParamAngleX=30` 头纹丝不动。
- **注视自研**（替代库的 `model.focus()`，已置 `updateFocus = () => {}`）：眼球 `ParamEyeBallX/Y`（可直接写，非物理参数）跟随 τ=0.09s；头部走 `AngleX/AngleY`（±9°/±6°）τ=0.32s。**眼快头慢 3.5 倍**是「先瞥一眼再转头」的关键。演出时 `gazeWeight` 淡出为 0（`holdGaze(归位窗口)`，与身体同一时刻交还），归位时 `releaseGaze()` 恢复。
- **`LeanInput` 符号**（2026-11-06 截图实测，早期注释写反过）：**负 = 前倾俯身凑近镜头**（人物被放大、肩膀被裁出画面），**正 = 后仰后撤**（人物变小、露出腰裙）。所以「指针在下方 → 俯身看她手边」= 负值；「指针在上方 → 上身微微后撤仰头」= 正值。
- **随机微动作（2026-11-06）**：待机时每 6~17 秒随机来一下小动作——`耳朵抖`(34%) / `耳朵连抖`(14%) / `歪头轻晃`(22%) / `身子一沉`(16%) / `抖完再晃`(14%)。不是开关式硬切，而是给弹簧一个冲量让它自己衰减振荡（半隐式欧拉 + 1/240s 固定子步，否则 120Hz 下峰值会被积分吃掉）。**演出中自动让路**（有姿势/动作/注视被 hold 时不触发）。耳朵走 `LEar1/2/3`+`REar1/2/3`（0=平摊下垂、0.35 半竖、1=竖起收拢），在 `beforeModelUpdate` 写入以覆盖物理输出；轻晃走 `AngleZ`、一沉走 `PositionY`（都进物理输入，头发裙子跟着甩）。钩子：`__fireMicro()` 立刻来一下、`__kickMicro('ear'|'tilt'|'sink',强度)`、`__setMicroEnabled(false)` 关掉、`__microState()` 看当前位移。
  - 上游本来有「眉毛 Y → LControl → 兽耳」的物理链（作者把挑眉做成竖耳），但实测写满眉 ±1 只让 LEar 动 0.03，肉眼看不见，所以直接写耳朵形变参数更可靠。
- **待机微摆（idle，2026-11-06 重写）**：模型自带的待机动作写的是 `ParamAngleX/Y/Z`，而这三个是物理**输出**、每帧被物理重算覆盖 → 待机摆动在我们的管线里等于被吃掉，静止时像块板。改为程序化补：`updateIdle(dt)` 驱动物理输入，**常驻叠在姿势与指针之下**。
  - **关键改法**：从**同一个相位 p**（周期 9.5s）派生所有通道、只错开相位差与倍频，而不是各通道各自独立周期。初版是四路独立正弦（0.37/0.29/0.23/0.47），看着像几个零件分别被风吹；改成同源之后才读得出「一个人在处理重心」。结构取自 `ref/jingyu` 的 sway 轨道。
  - 通道：`PositionX` 3.0·sin(p) / `PositionY` 1.5·sin(2p+0.4) / `PositionZ` 1.8·sin(p−0.35) / `AngleX` 2.2·sin(p−0.6) / `AngleY` 1.2·sin(2p−0.3) / `AngleZ` 2.0·sin(p−0.45) / `LeanInput` 1.6·sin(2p−1.1)。
  - `__setIdleScale(0~3)` 调总幅度，`0` 即关掉。
- **说话层（speech，2026-11-06 新增）**：解决「说话动作不灵动」。
  - **根因**：原来 `handleSpeak` 只是从 `POSTURES` 里挑一个大姿势（歪头/抬头/前探），`postureCur` 用 τ=0.12s 平滑过去**然后就静止了**——一句说 5 秒，前 0.5 秒动一下，剩下 4.5 秒只有 idle 那 2° 底噪，观感是「说一句、动一下、变成雕塑」。真人的说话是连续量：音量起伏带着下巴走、句子有节奏地点头、句读处松一下、身体一直在换重心。这些选不出来，只能**叠一层常驻的continuous 驱动**。
  - **信号链**：`analyser` 的 RMS（与口型同源，`playVoice` 的 rAF 里写入 `speechRaw`）→ `level`（快升慢降，升 τ=55ms / 降 τ=190ms）→ `floor`（慢速基线 τ=0.9s）→ `accent = max(0, level − floor − 0.04)` → **重音弹簧**（半隐式欧拉 + 1/240s 子步，k=190 / c=21 / 力系数 380）。
  - **力系数是大坑**：初版给 34，稳态位移只有 `34×accent/190 ≈ 0.13` = 0.1° 点头，实测完全看不见。改成 380 后峰值 1.49（≈1.5），点头动态范围 4°，才「每句话都看得出在点」。
  - **叠加量**（都乘权重 `w`）：`AngleY` −0.9 −onset·0.85 −level·0.55（基础微低头 + 重音点头，负=低头）；`AngleZ` 慢摆 1.7 + 快频 0.45；`AngleX` 极慢游移 1.7；`LeanInput` −2.4 −level·1.5（前倾投入）；`PositionY` 慢浮 0.7 −level·0.45；眉毛 `ParamBrowLY/RY` +level·0.17+onset·0.06（在 `beforeModelUpdate` 写，满幅 1，给 0.15~0.3 刚好，再多就成惊讶脸）。
  - **权重**：`playing` 为真 → τ=0.15s 起势；语音停 → τ=0.9s 自己退场，**不需要谁去「收姿势」**（这也是「说完就归位」自然的原因）。纯文本无音频的回复走 `speechFallbackUntil` 兜底：只有基础前倾+摆动，没有重音和眉毛，避免「有气泡没声音的那些回复」完全没有身体语言。
  - 钩子：`__speechState()` 看 `{w, level, floor, onset}`。
- **演出期注视不再全掐（2026-11-06）**：原来 `holdGaze` 期间 `gazeWeight` 淡到 **0**，说话那几秒她的头一动不动（只有 idle 底噪）——这是「不灵动」的另一半原因。改成保留 **35%**：仍然看着你、跟着鼠标微调，只是不再大幅转头抢戏。
- **渲染分辨率（2026-11-06）**：`PIXI.Application` 必须传 `resolution: devicePixelRatio, autoDensity: true`。本机窗口跑 125% 缩放，默认 `resolution=1` 时 canvas 只有 380×780 像素却被系统拉到 475×975 显示 = 整幅画面低分辨率渲染后软放大，所有斜边（尾巴、发丝）呈阶梯状。改完 canvas 变 475×975，尾巴/头发边缘立刻平滑。
- **尾巴那圈浅色边的真相**：不是渲染 bug，也不是擦图造成——统计 `texture_00.png` 与其 `.bak` 的 alpha 边缘像素，亮度分布几乎一致（边缘平均亮度 113 / 亮像素占 31% vs 备份 110 / 30%），即素材自带的浅色羽化描边。参考项目「尾巴没这问题」是因为那跑在不透明场景页里、浅边被背景吃掉，且尾巴贴图本来就不同。要彻底消掉只能改贴图（半透明边缘 RGB 向内取色），属于美术级改动，非必要不动。
- **帧率无关平滑**：姿势过渡与注视统一用 `1-exp(-dt/τ)`（`τ=0.12s`），不再用固定系数（原 `+= (t-c)*0.14` 在 144Hz 下会 4 倍速窜过去）。
- **参数雷区**：`Param33`（原"并腿"）也是物理输出，写它无效；`Movement2`（抚胸）是物理输入，可安全直写；物理输出共 292 个（见 `大肥鱼.physics3.json`）。
  - **回音修复**（v0.3.2）：两层根因。①`api.dsh` 事件总线不在 aurabot 的 stop 清理范围里、`on()` 返回值也不是可靠 disposer，热加载 N 次就累积 N 个监听器、每个还带私有去重表 → 同句投 N 遍。改为 `globalThis.__live2dBridge` 存**代际令牌**（`gen`）+ 跨实例去重表，旧代监听器一看到令牌对不上就空转。②渲染端 `stopVoice()` 原来只置 `playing=false`、**从未 stop 真 source**，多句并发解码后各自 start → 同一段音频错开几十毫秒叠播，听感就是回音。改为持有 `voiceSrc` 真 stop + `voiceSeq` 播放序号（被顶掉的那段解码完直接丢弃）+ 同文本 3 秒兜底去重。验证脚本 `echotest.cjs`。

## 六、语音入口（0.16.0，给壳的备忘）

一共四条路，**共用同一条会话**，落点由 `pet.json` 的 `talk.to`（`qq` / `system`）一个开关决定：

| 入口 | 触发 | 谁在听 |
|---|---|---|
| 叫醒词 | 说「小鱼小鱼」 | 常驻 16k 采集 + sherpa-onnx KWS（离线，4.6MB 模型）；命中先应一声再进识别 |
| 按住说话 | 按住 F1 | `uiohook-napi` 全局钩子；未装则此路不可用 |
| 电话 | 右键菜单 | 一直听、自动断句、能插话 |
| 陪看 | 右键菜单 | 按画面变化筛帧 |

- **叫醒词引擎**：`app/wake.js`（主进程，`sherpa-onnx-node` 的 `KeywordSpotter`）+ `app/renderer/wake.js`（采集与应答）。
  平台包路径是 `node_modules/sherpa-onnx-win-x64`（npm 名叫 `win`，不是 `win32`），**require 前要把它塞进 `PATH`**，
  否则只会报「找不到模块」，看不出是缺 DLL。N-API 模块，**不需要 electron-rebuild**。
- **唤醒→识别是一条流水线**：`idle → acking（应答）→ arming → speech → 送出`。应答期间**保留 pre 缓冲**，
  所以应答那 0.4~0.5 秒里说的话不会被吃掉开头。`armUntil` 必须在进入 `arming` 时**重赋**，否则会用旧时刻立刻判超时。
- **F1 在任何非 idle 阶段按下 = 取消**：`cancelWake()` + `ears.cancel()`，这一句不上送。
  `getUserMedia` 是异步的，取消常早于 `recording=true`，所以 `ear.js` 有 `abortPending` 标记。
- **应答音**：`app/renderer/wake-ack-{1,2,3}.wav`（48k，edge-tts 同音色：zh-CN-XiaoyiNeural）+ `wake-chime.wav` 备选。
  播放走 Web Audio（`decodeAudioData → BufferSource`），跟她说话的通道一致；用 `new Audio()` 会因通道不同而听感不一致。
- 面板开关：`pet.json` 的 `wake = { on, ack, ackMode: 'voice'|'chime'|'off', word }`。
  **新安装默认关闭**（`on === true` 才开启），只有用户主动启用后才采集麦克风。
- 模型目录在私有 `state/live2d/pet/models/kws/`（5 个文件）。替换唤醒词要同时改 `_active.txt` 和面板里的中文词；
  词表里**不要同时放「小鱼」和「小鱼小鱼」**，短词会抢路径。

## 七、她自己造动作（2026-11-06）

她手上有三个工具：

| 工具 | 做什么 |
|---|---|
| `live2d_motions` | 列出动作库（名字 + 何时用 + 轨道数），造之前先看，别重复 |
| `live2d_dict` | 查参数词典（466 个参数的名称/量程），确认关节名和幅度 |
| `live2d_make_motion` | 造动作：名称 + 何时用 + 轨迹 JSON + 时长（+基底/表情/关键词） |

校验会拦下：不存在的参数名、超出量程的值（自动夹回）、非法通道前缀、
时间轴倒序、超过 24 条轨道、非法表情名。写完立刻落盘 `clips.json`，
渲染页 3 秒内热加载 —— 下一句话就能演。同名会覆盖，方便「照着主人的意见改」。

她还能给动作写 `tags`（关键词），主人说的话命中这些词、而她又没点名动作时，
模块会自动帮她配上这个动作（面板里「语义自动配动作」开关）。

HTTP 自测：`GET /api/mhub-community/live2d/ext/live2d/motions`、`POST /api/mhub-community/live2d/ext/live2d/make-motion`。
